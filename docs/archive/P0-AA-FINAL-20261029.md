**結論：目前 P0 網站的 WCAG 2.1 A／AA 評估通過：39 通過、10 不適用、1 已廢止，0 個未處理失敗或待驗準則。** 這是指定範圍的工程驗收，不是第三方標章或正式 server 的認證。使用者指定不以 NVDA 作必要驗收工具；本輪使用內建 Browser 與隔離 Orca／Firefox，不啟動主機讀屏。

## 範圍、來源與證據方法

S：原始 Excel「功能規格」E34／G34／L34、串接總覽 B15；依 [WCAG 2.1 正式標準](https://www.w3.org/TR/WCAG21/) 評估，不將 WCAG 2.2 新準則冒稱業主原要求。U-20：2026-10-29 使用者要求「請做修改並做完整AA 但應該不需要NVDA」。標準的合規要求以無障礙支援與成功準則為依據，沒有指定必須使用某一品牌讀屏；工具選擇不豁免準則。

範圍為目前已串接的 P0 固定頁／發布詳情、共用元件及登入／失敗／草稿／發布／到期等流程。不包含尚未實作的 P1／P2 管理功能，也不宣稱任意未來上傳素材都自動合格。

- **B（沿用基線）**：[10月26日逐項證據](P0-AA-VERIFICATION-20261026.md)、[10月25～26日完整紀錄](P0-COMPLETE-VERIFICATION-20261025.md)；含真正200%／400%、文字間距、直橫向、文字／欄位及12類圖片對比、既有表單與狀態的輔具證據。對應來源與規則未變，逐項核對影響範圍後沿用；不是今日重新逐頁重跑。基線曾使用 NVDA，是有效歷史證據，並非本輪指定或重新執行。
- **R（本輪／同日補驗）**：[完整 Browser 對照](P0-BROWSER-VERIFICATION-20261029.md)的40頁桌手機、10個核心頁載入後320px與真實業務；本輪再盤點68固定頁、8網址320px文字間距、新模態初始／雙向焦點、到期／錯誤／恢復，以及真 Orca 的完整預警、到期說明與無效欄位辨識。viewport不是實際瀏覽器縮放；實際縮放證據明確歸B。

本輪完整逐項評估使用可追溯的 B＋R，不把歷史失敗抹掉，也不以工具安裝、AX tree或語音事件數代替互動測試。

## 修正及實際結果

1. 到期提示先聚焦具 tabindex=-1 的標題，關聯完整說明與登入帳號；首次 Tab／Shift+Tab 進入第一／最後控制項，模式由預警轉到期時重新聚焦訊息。Orca 實際自動讀出完整標題、延長方法與帳號，不再只讀按鈕。
2. 進度使用 polite status，錯誤另用 assertive／atomic alert，密碼欄以 describedby 關聯；最後版本直接聚焦錯誤摘要，Tab進入密碼欄，Shift+Tab及Escape可操作。失敗後清除密碼、保留草稿，恢復不自動重送保存。Browser實際AX與焦點包含完整錯誤文字；Orca已辨識欄位／invalid entry，但未取得完整錯誤字句的自動語音，不能把瀏覽器密碼提示或工具掉字算成網站結果。依[W3C 3.3.1](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html)核對文字錯誤辨識；依[4.1.3的範圍](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html)，會接收焦點的錯誤摘要屬context change，不另要求無焦點自動播報。這是準則本身的界線，不是NVDA豁免或把輔具失敗改寫為成功；獨立role仍保留。沒有儲存密碼。
3. 320px加大文字間距的預警框約273×414 CSS px，內容不需內部捲動、兩個按鈕可見；8個網址無整頁水平溢出，載入後的景點編輯／設定已核對。正常樣式與1800／43200秒期限已恢復。
4. 新增 `frontend/tests/session-prompt.test.mjs` 三個可觀察行為測試：初始雙向Tab、模式轉換、失敗關聯／密碼清除／焦點返回。Docker完整前端174項通過；清理後68固定頁／16資產／84 HTTP、issues 0。沒有PHP／API／DDL修改；既有真MariaDB 51項期限與權限拒絕證據保持，沒有降低session安全上限。

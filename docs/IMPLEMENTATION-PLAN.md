## 1. 現況與確定架構

已核對文件與使用者回覆：客戶目前未指定部署主機或技術版本。Excel 七個工作表未限定 PHP 版本、資料庫產品／版本、PHP 框架或 Apache／Nginx；「SEO規格」E17 提到「PHP/伺服器模板輸出」，是 SEO 輸出方向，並非限定整個後端只能使用 PHP。「串接總覽」A2 明示標記「建議」的內容為需依團隊技術架構確認的提案。使用者已指定採用新版本 PHP＋MariaDB、Docker 啟動，前端 JavaScript 允許使用 jQuery。以下架構依此定案。

- 原始 website 有 57 個獨立 HTML 頁面、共用 CSS，以及約 92 KB 的 js/app.js；已有前台、內容詳情、後台列表與新增／編輯畫面。
- 現有前端使用 jQuery 3.7.1；正式版可保留 jQuery 的操作方式並升級至 4.x，拆分 JavaScript 模組與共用 API 工具，沿用現有版型、RWD 與網址結構。
- 本次提供的網站內沒有 PHP、資料庫建置檔或正式 API。PHP 是本案預定技術，不能據此認定客戶已有 PHP 後端。
- 原始 website 的模擬登入僅檢查表單格式與密碼長度；後台可切換模擬管理員，預設使用 root。內容、收藏、行程、設定都在 localStorage，不具正式認證或跨裝置同步。
- 部分詳情與編輯操作使用陣列位置作識別，正式資料需改用穩定 ID／slug，避免刪除、排序、分頁後指向錯誤內容。
- 本機 Docker Engine／Compose 已驗證，PHP 與資料庫由容器提供，不要求主機額外安裝。Nginx 提供 frontend/dist 與 PHP API 的 FastCGI 路由；階段二認證、管理員與權限已實作，MariaDB yinghua 已建立業務表。開發入口為 http://localhost:8080/；website 仍保留原始交付。

後端採 PHP 8.5、PDO 與 MariaDB 12.3 LTS，使用清楚分層的路由、控制器、服務與資料存取層。前端採原生 JavaScript，不引入大型前端框架；jQuery 是使用者允許的可選工具，本階段沒有需要而未引入。MariaDB 12.3 是目前最新的長期支援系列；13.0 為較新的 rolling 系列，本案選用 LTS 作為持續維護基礎。實作時再次核對安全修補版本，將可用容器映像鎖定至明確修補版本／digest，不使用浮動 latest。

版本依據：[PHP 官方支援週期](https://www.php.net/supported-versions.php)、[MariaDB 官方版本清單](https://mariadb.org/)、[MariaDB 維護週期](https://mariadb.org/about/)、[jQuery 官方下載](https://jquery.com/download/)。後續若使用 jQuery 4，再確認 DOM／事件／動畫相容性；目前沒有載入原型 jQuery 或外部 script CDN。

前台與 API 以同網域部署，API 統一 /api/v1。會員與管理員採分開的認證流程與授權邊界。PHP 只提供 API，由 Controller／Service／Repository 處理請求、流程與資料；HTML／CSS／JavaScript View 在 frontend/。公開 SEO 內容由前端建置／預先產生 HTML 保留，不能只在瀏覽器修改 head；此建置方案是工程補充 E-12；API 由共用 fetch 工具統一處理 CSRF、錯誤與登入逾時。

使用者指定的資料庫登入帳號為 spl，資料庫名稱仍為 yinghua。此設定用於資料庫登入；網站顯示名稱不變，Docker 專案名稱為 yinghua，PHP 命名空間 Yinghua 已用於本階段程式，並非技術使用者名稱。

目錄原則：website/ 保留原始交付網站及原有文件，不寫入新增工程文件或程式。新增計畫、需求對照與驗收文件放在 project/docs/；後端放 project/backend/，前端來源放 project/frontend/。backend/ 與 frontend/ 於階段二首次建立；PHP 品質工具套件仍獨立放 tools/php/，與應用 manifest 分開。

公開網址保留 .html 形式：例如 /films/{slug}.html 由前端內容產生工具自動建立，再由 Nginx 提供。新內容直接有可開啟網址，不需要每筆手工複製 HTML。既有 film-detail.html?id=... 等入口建立穩定資料對照與轉址；不能把舊陣列索引直接當新資料庫 ID。

### Docker Compose 環境

| 服務 | 配置與責任 |
| --- | --- |
| web | Nginx 官方穩定映像；提供 frontend/dist 靜態 HTML／資產及 PHP API FastCGI 路由，別名網址轉至 APP_URL |
| app | 自建 PHP 8.5 FPM 映像，安裝 pdo_mysql、mbstring、intl、gd 及所需 HTTP／媒體支援；目標只執行 HTTP API，另提供必要 CLI |
| db | MariaDB 12.3 LTS；utf8mb4、專用應用帳號、健康檢查、持久化資料 volume |
| 開發郵件服務 | 以可選 Compose profile 提供郵件測試；正式環境使用客戶 SMTP |

- 使用 compose.yaml、PHP Dockerfile、Nginx 路由設定與 .env.example；正式環境另有設定覆寫，秘密值不提交原始碼。
- 預定以 docker compose up -d --build 啟動整套服務；初始化 migration 與 root 設定有獨立、可重跑命令，不在每次重啟時重置資料或寫入示範帳號。
- 資料庫與上傳檔使用持久化 volume；正常重啟／重建 app 容器保留資料，備份與還原同時涵蓋資料庫及媒體。
- DB 健康後才開始需要 DB 的初始化／應用檢查；登入、發布等流程驗收以真實 MariaDB 執行，不以其他引擎替代資料庫整合測試。
- 資料庫只在 Compose 內部網路提供；有必要從本機工具連線時，使用開發設定綁定 localhost。正式對外入口使用 HTTPS。
- 開發模式掛載程式碼方便修改，正式模式建立可部署映像；排程任務提供容器化執行命令與部署方式。

## 3. 各模組實作內容

### 前台內容

- 電影：電影資料與場次拆開，一部電影可有多個場次；依 Asia/Taipei 計算本週，檢查開始／結束與場次衝突。
- 活動與消息：type 固定 event／city，保存摘要、正文、封面及活動區間；正文使用安全富文字白名單；列表下半部能分頁瀏覽全部文章。
- 優惠：獨立資料與頁面，關聯店家、期間與使用條款；有效清單排除草稿及過期項目，已發布的過期詳情顯示過期狀態。
- 推薦路線：展示主題、時間與有序站點；發布／套用前檢查至少一個有效景點，不把已下架景點新增到會員行程。
- 詳情及前後篇：依主題／分類與穩定排序取得已發布相鄰內容，有縮圖和標題；無相鄰內容就不產生空連結。直接網址可開啟，無燈箱；不存在或未發布回真正 HTTP 404。
- 全站搜尋：景點、美食、電影、消息、優惠按類型呈現，可篩選及分頁，使用公開狀態及期間規則，不漏出草稿。

### 會員

- 註冊與登入：Email 正規化與唯一約束、密碼雜湊、伺服器驗證碼、同意條款版本、欄位錯誤、登入限速與鎖定、登出及密碼重設。
- 圖形驗證碼：答案不回傳前端，短效、一次性、限次、綁定註冊流程；提供重新取得及可用的無障礙替代方式。
- 收藏：新增／移除／載入，資料庫唯一約束避免重複；補上可查看本人收藏的入口。
- 行程：支援多份行程的清單、名稱／日期、站點順序、時間／備註、保存與刪除，保留現有 planner 的編輯體驗。
- 未登入操作收藏或加入行程時導向登入並保留返回目的；登入後重新確認目標仍可使用。
- 每次行程／收藏讀寫都由後端檢查本人所有權。新增站點不能重複或引用已刪景點；既有行程保留景點名稱快照並標示下架，不靜默遺失整份行程。
- Email 驗證是交接文件提案：資料模型預留，是否強制驗證後才能操作需依客戶會員政策確定，不默認擴大合約。

### 管理後台

- 新增獨立管理員登入與登出；移除模擬身分切換。後台頁面與所有管理 API 均有伺服器授權。
- 景點、電影、消息、優惠、路線均保留獨立列表／新增／編輯頁；刪除使用確認與狀態通知，不新增刪除專頁。

- 角色以 Excel 權限矩陣作預設，允許逐人調整 view／create／edit／delete；前端依 API 返回權限顯示操作，後端每次重新驗權。

- 權限異動立即影響後續請求，停用帳號撤銷 session；不允許非 root 藉管理其他帳號授出自己沒有的權限。

- 儀表板使用具授權的實際統計；稽核保留內容、權限及設定異動，不保留密碼、token 或未遮罩敏感資料。

### 圖片與 Google 地圖

- 圖片改為媒體上傳，保存 mediaId、URL、尺寸、alt、來源與授權。限制檔案 MIME、實際影像格式、大小與尺寸，禁止作為可執行檔使用。
- 初期以部署主機的受控媒體目錄實作，抽象儲存介面；客戶有物件儲存時再接相同介面。上傳能力綁定相應內容模組權限，避免新增角色不必要的全域管理權。
- Google Maps 解析由 PHP 完成：限制 HTTPS／允許網域、每次 redirect 驗證、阻擋內網及保留 IP、設定逾時與重導向上限，再接 Places 查詢。
- 解析只預填候選資料，必須由管理員檢查後儲存；有錯誤訊息及人工編輯路徑。API Key 留在伺服器，費用／配額及服務啟用由客戶帳號提供。
- 地圖文字與照片的可保存範圍、來源標示依啟用服務條款另行確認；不自動把第三方照片當成本案授權素材。

### 網站設定與 SEO

- 全站名稱、摘要、聯絡信箱、條款與隱私版本存資料庫；補上可閱讀政策的頁面及註冊同意欄位。
- 全域 SEO、逐頁覆寫與單筆內容 SEO 統一優先順序：內容覆寫 → 頁面覆寫／範本 → 全站預設。
- 公開前端 HTML 包含唯一 title、description、canonical、OG、Twitter Card、favicon 及適用 JSON-LD，由前端內容產生流程維護；不能只用瀏覽器 JS 修改 head，PHP 提供內容／設定 API。
- 分享圖是匿名可讀的正式絕對 HTTPS 網址。後台與私人頁強制 noindex，不能被全站設定覆寫。
- robots 與 sitemap 自動依正式網域與已發布、可索引內容產生；內容異動使頁面、列表、前後篇與 sitemap 快取失效。
- 既有網址轉換為新 slug 時建立 301 對照；canonical 移除追蹤參數。正式域名未提供前用設定值，不把 localhost 寫入正式網站地圖。

## 6. 驗收方式

API／整合測試重點是規格中的資料與權限邊界；每階段先跑相關測試，再驗收該模組的完整瀏覽器流程。

1. 認證：重複 Email、錯誤／過期／重送驗證碼、登入失敗與限速、密碼重設、登出後 401、管理員與會員 session 不互相授權。
2. 權限：直接偽造 API 也不能修改 root、越權編輯、替他人讀寫行程，權限被撤銷後下一個請求失敗。
3. 內容：新增 → 上傳 → 草稿 → 發布 → 前台 → 修改 → 下架；各列表、詳情、前後篇與首頁同步，API 成功前不顯示保存完成。
4. 日期：週邊界、台北時區、排程發布前後、優惠最後一天與過期、場次開始／結束／衝突。
5. 關聯：景點被路線／行程引用時刪除的處理、重複站點、空路線、排序完整性、版本衝突回 409。
6. 圖片／網址：非法檔案、超過大小、alt、圖片失敗替代圖、合法與非法 Google 網址、重導向／逾時、無 API 配額時人工輸入仍可保存。
7. 頁面：手機／桌面、鍵盤操作、讀屏錯誤關聯、焦點、對比、縮放、無資料／載入失敗／重試及真正 404；依 Excel 目標檢核 WCAG 2.1 AA。
8. SEO：不執行 JS 檢查 HTML source，逐頁 title／摘要／canonical，JSON-LD 一致性，分享預覽，sitemap 排除私人／未發布內容。
9. 部署：Docker Compose 冷啟動、空 MariaDB migration 與 seed、容器重啟後資料／上傳檔保留、排程工作、備份還原、機密目錄無法公開存取、health 及錯誤紀錄不暴露內部資訊。

建立「Excel 功能規格列 5–34 → 實作模組 → 測試／人工驗收 → 結果」的對照表，避免僅按畫面有無判定完成。

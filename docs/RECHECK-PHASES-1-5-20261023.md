## 漏驗原因、修正與回歸

景點編輯頁選擇新圖片、尚未上傳，確認「重新載入」後，文字與媒體 ID 恢復，但原生檔案選擇器仍保留新檔案；dirty 已歸零，下一次保存卻會被「尚未上傳」阻擋。先前只驗文字重載、圖片上傳成功及保存，沒有把「選檔但未上傳」列入重載的組合，驗證結論因此過廣。

- `frontend/assets/js/pages/attraction-form.js` 僅在成功讀回伺服器資料後清空檔案選擇；取消或載入失敗保留選檔。
- `frontend/tests/attraction-form.test.mjs` 新增兩例，執行真正表單邏輯與原生 file input 邊界：取消保留、確認清空並可保存原媒體、失敗保留／成功重試清空。修正前新增案例確實失敗，修正後通過。
- 瀏覽器實際重現修正前 `C:\fakepath\poster.png` 殘留；修正後取消仍保留，確認並等待載入完成後 value 為空、儲存恢復可用。主站沒有按上傳或保存，不改正式內容。
- 新增 [V01–V18 固定清單](VERIFICATION-CHECKLIST.md) 及可重跑的 `backend/tests/frontend_integrity.py`，補上這次漏掉的狀態和全固定頁結構／資產檢查。後續不能只把當次想到的案例跑完就宣告全部完成。

# Git 分支與提交

第一筆提交保留原始交付的網站與規格，永不修改。15 個階段的分支與合併歷史見 [archive/GIT-WORKFLOW-HISTORY-20261103.md](archive/GIT-WORKFLOW-HISTORY-20261103.md)。

## 提交流程

- 每項工作從當時最新 `main` 開始；分支保留，驗收完成以 merge commit（`--no-ff` 或 GitHub PR 的 merge）合併。合併前以 `git bundle` 備份，合併後確認最終 tree 與原始交付提交完整保留。
- 每筆功能含必要後端、前端、API 契約、測試及中文指南；共用前置環境另作明確準備提交。不要只按目錄／副檔名拆分，也不要把整階段擠成一筆。
- 原型公開頁的提交明示保留原型，不冒充後續模組的正式 API。
- 真正新增的需求另作完整功能提交；代理自身失誤歸回原功能。階段內的文件、規格對照及複查隨功能／驗收交付，不另造進度分支。
- 尚未分享的本機階段歷史，可在備份與驗證後收整為一個完整階段合併點。已分享的歷史不自行覆寫遠端。
- 架構或操作有變時改寫 [PROJECT-GUIDE.md](PROJECT-GUIDE.md) 對應段落；本次完成的內容與驗證結果寫入 [CHANGELOG.md](CHANGELOG.md)。
- 合併只表示紀錄中實際通過的範圍，不代表正式 SMTP、HTTPS 或其他正式環境待驗項已完成。
